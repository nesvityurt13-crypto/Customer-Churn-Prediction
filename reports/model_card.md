# Model card: Customer Churn Prediction

## 1. Общая информация

- **Модель:** Random Forest classifier для прогнозирования оттока клиентов.
- **Версия:** 1.0, учебная.
- **Тип задачи:** бинарная классификация (`Churn = Yes` / `No`).
- **Репозиторий:** https://github.com/nesvityurt13-crypto/Customer-Churn-Prediction
- **Статус:** демонстрационная модель для портфолио, не готова к автоматическому принятию решений в production.

## 2. Назначение

**Для чего используется:**

- ранжирование клиентов по вероятности оттока;
- приоритизация контактов отдела удержания;
- анализ сегментов с повышенным риском;
- учебная демонстрация полного цикла ML-проекта.

**Для чего не используется:**

- автоматическое расторжение договора или изменение условий;
- кредитные, страховые или иные решения о клиенте;
- дискриминация клиентов по полу, возрасту или другим признакам;
- перенос на другую компанию или рынок без дополнительной проверки;
- расчёт гарантированного ROI или причинно-следственных эффектов удержания.

Решение модели должно использоваться только как один из факторов и с участием человека.

## 3. Данные

- **Источник:** IBM Telco Customer Churn (Kaggle).
- **Объём:** 7 043 клиента, 21 столбец.
- **Целевая переменная:** `Churn`, доля оттока 26,54% (1 869 клиентов).
- **Признаки:** 19 исходных столбцов после удаления `customerID`.
- **Тип данных:** один демонстрационный срез без временной истории.
- **Пропуски:** `TotalCharges` содержит 11 пустых значений, все при `tenure = 0`; заполнены нулём.
- **Дубликаты:** 22 строки совпадают по признакам после удаления `customerID`; это разные клиенты, строки сохранены.
- **Чувствительные признаки:** `gender` и `SeniorCitizen` используются моделью. Справедливость и отсутствие дискриминации отдельно не проверялись.

## 4. Модель и обучение

- **Pipeline:** медиана + `StandardScaler` для числовых признаков; most frequent + `OneHotEncoder` для категориальных; `RandomForestClassifier`.
- **Гиперпараметры:** `n_estimators=200`, `max_depth=10`, `min_samples_leaf=10`.
- **Разбиение:** 80/20, стратифицированное, `random_state=42`.
- **Подбор:** `GridSearchCV`, 5-fold `StratifiedKFold`, scoring = PR-AUC.
- **Порог:** 0,2781, выбран по out-of-fold предсказаниям при требовании Recall ≥ 0,80.
- **Число признаков после One-Hot Encoding:** 40.

- калибровочная кривая близка к диагонали.

Порог 0,2781 соответствует отношению стоимости FN/FP между 2 и 5. Это анализ чувствительности, а не расчёт реального ROI.

## 6. Интерпретация

Наибольший вклад в модель дают:

- `Contract_Month-to-month`;
- `tenure`;
- `TotalCharges`;
- `MonthlyCharges`;
- отсутствие техподдержки и онлайн-защиты;
- `InternetService_Fiber optic`;
- `PaymentMethod_Electronic check`.

Permutation importance на тесте выделяет `tenure`, `Contract`, `TotalCharges`, `InternetService`, `TechSupport` и `OnlineSecurity`. Расхождения с встроенной важностью объясняются корреляцией признаков и разным уровнем детализации: исходный признак против one-hot категорий.

Важность признака не доказывает причинно-следственную связь.

## 7. Ограничения

- Данные демонстрационные, один временной срез без истории поведения клиентов.
- Нет временной валидации; модель не проверена на будущих периодах.
- Нет реальных стоимостей контакта, скидки и эффективности удержания.
- Тестовая выборка небольшая: 1 409 клиентов, 374 ушедших.
- Справедливость модели по полу и возрасту не оценивалась.
- Вероятности достаточно калиброваны, но не идеальны.
- Важность признаков не является доказательством причинности.
- Модель может деградировать при изменении клиентской базы, тарифов или рынка.

## 8. Как использовать

Скрипт для скоринга:

```powershell
.\.venv\Scripts\python.exe scripts\predict.py data\new_clients.csv
```

Параметры:

- `input` — CSV с 19 признаками клиентов;
- `--model` — путь к модели, по умолчанию `models/churn_model.joblib`;
- `--output` — путь для результата, по умолчанию `reports/churn_predictions.csv`;
- `--threshold` — порог вероятности, по умолчанию `0.2781`.

Результат содержит:

- `customerID`, если он есть во входном файле;
- `churn_probability` — вероятность оттока;
- `predicted_churn` — 1, если вероятность не ниже порога, иначе 0.
